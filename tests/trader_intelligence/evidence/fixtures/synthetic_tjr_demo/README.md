Every JSON/text file under this directory was generated by
`scripts/trader_intelligence/generate_synthetic_tjr_fixture.py` for
PROGRAM-006 Phase 1B (ADR-009, Deliverable 20). None of it is real TJR
research, a validated trading claim, or a production rule.

It exists to demonstrate the full explainability + controlled intake
pipeline end to end, driving it through both intake manifests exactly the
way a real transcript would (parse → segment → suggest → annotate → apply →
question/propose/queue), never by writing evidence/claim records directly
except where explicitly noted below.

## What it contains

- **2 IntakeManifests**: a 15-segment multi-topic timestamped-text transcript
  (Intake 1) and a short plain-text corroborating owner note (Intake 2, an
  independent second source used to demonstrate cross-source confidence
  discounting).
- **15 TranscriptSegments** (Intake 1) covering: an explicit rule statement
  (repeated once, verbatim, to exercise exact-duplicate detection), an
  implied rule, a demonstrated chart example, a hedge/contradiction, an
  unsupported opinion, an exception, a discretionary statement, a success
  observation, a failure observation, a risk statement, a scoped variant
  (same rule text, explicit 15-minute timeframe), an ambiguous stop
  placement, and an explicit unresolved question.
- **14 ManualAnnotations**, each approved and applied through the real
  pipeline (`annotation_pipeline.apply_annotation`) -- nothing here bypasses
  annotation review.
- **9 Claims**, deliberately spanning every confidence outcome the milestone
  requires:
  - `CLAIM|TJR|...|001` ("Displacement occurs after a liquidity sweep.") --
    **`confidenceState: supported`** (~46.8), from two independent source
    groups (an explicit statement + a demonstrated chart example from
    Intake 1, plus an independent corroborating statement from Intake 2).
  - `CLAIM|TJR|...|002` -- the same claim text with an explicit `timeframe:
    "15m"` scope. A genuinely **separate** claim (scope must matter), linked
    only advisorily via `possibleDuplicateClaimIds`, never merged.
  - `CLAIM|TJR|...|003` ("A confirmation candle is required before entry.")
    -- **`confidenceState: contested`**, from an implied-requirement
    statement contradicted by an explicit hedge, further weakened by an
    unsupported opinion.
  - `CLAIM|TJR|...|004` (exception claim) -- contradicted, via a
    `ContradictionRecord`, against claim 003.
  - `CLAIM|TJR|...|005` -- registered directly with **zero evidence**
    (`confidenceState: insufficient_evidence`), representing a legitimately
    open research placeholder rather than an extraction artifact.
  - `CLAIM|TJR|...|006` (`stop_rule`) -- ambiguous stop placement, only weak
    inferred support.
  - `CLAIM|TJR|...|007` (`trade_management_rule`) -- discretionary statement.
  - `CLAIM|TJR|...|008` (`behavioral_observation`) -- success observation
    contradicted by a failure observation.
  - `CLAIM|TJR|...|009` (`risk_rule`) -- explicit risk statement.
- **1 ContradictionRecord** between claims 003 and 004.
- **17 EvidenceQuestions**, deterministically generated by
  `evidence_questions.py` (missing timeframe/session, missing invalidation,
  discretionary management, self-contradiction, insufficient independent
  support, missing replay/paper validation, etc.).
- **1 RuleCandidateProposal**, auto-suggested by
  `extraction_pipeline.run_post_annotation_pipeline` for claim 001 the
  moment it reached `supported` -- `status: "proposed"`, never active.
- **Review queue entries** across all 14 queue types (see
  `review-queue/`), rebuilt by the same post-annotation pipeline run.
- **`reports/claim_a_explanation.json` / `.txt`** -- a full, traceable
  explainability report for claim 001, both machine- and human-readable.
- **`reports/tjr_research_report.json` / `.md`** -- a complete TJR research
  report for Intake 1, covering all 25 required sections.

## Never confuse this with real data

Nothing here is ever read by production code, `build_graph.py`, or anything
under `docs/trader-intelligence/`. `validate_evidence.py --allow-synthetic`
(equivalently, `is_production=False`) is the only mode in which this
directory's synthetic markers are not flagged as a leak.
