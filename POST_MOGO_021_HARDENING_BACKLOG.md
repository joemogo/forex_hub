| B-23 | **RESOLVED.** Five Python suites asserted a corpus snapshot instead of an invariant (`nodes == 43`, `edges == 79`, `questions == 12`, `phase7a_nodes == []`, evidence tree empty). Three of them asserted a tree that MOGO-022's own authorised import deliberately filled. An independent verifier defeated the first rewrite in five ways, all since fixed and re-verified: the contentHash assertions computed the expected value with the same `content_hash_of` the builder used (gutting it to drop every list/dict field left everything green — the tests now compute the hash independently); the read-only test fingerprinted 5 of 19 evidence subdirectories and was defeated by a sibling test that ran the build first (now all subdirectories, comparing mtime as well as content); `len(edges) > 0` was satisfied by 1 edge instead of 5142 (now an identity-pinned edge-type set plus an independently derived `BELONGS_TO_TRADER` count); the per-category non-emptiness guards let a whole node type vanish (now per node type); and the blocking-question filter shared its expression with the implementation (now a stub-index positive control forcing `answerStatus` and `researchStatus` to disagree). |
| B-24 | **Three coverage gaps left open by B-23, recorded rather than claimed closed.** (a) `discover_entities` fabrication is only caught for the 9 Phase 1B/7A node types, which re-read their entity from `sourceFile` on disk; for the ~17 Wave-1 types a wrong-but-existing `sourceFile` is invisible, because the graph test compares against the same generator the build used. (c) The `DUPLICATE_NODE_ID` FATAL guard has no positive control — deleting it breaks nothing, since the corpus contains no duplicates. Per the standing rule, a guard is not evidence until removing it makes something fail. |
