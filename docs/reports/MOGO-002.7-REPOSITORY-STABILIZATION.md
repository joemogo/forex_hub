## 1. The situation in one paragraph

`HEAD` is `a332d04` (*PROGRAM-007 Phase 7A*, committed 2026-07-26). Since then the repository has
accumulated **three completed engineering milestones, five research-ingestion cycles including two new
educators, and 6,674 untracked files** — none of it committed, tagged, or pushed. The working tree is
the **only copy** of all of it. A single `git clean -fd`, a failed `git checkout`, or a disk loss would
destroy roughly 32 MB of provenance-tracked research and three review packages that took real work to
produce. **This is the largest operational risk in the repository, and it is larger than any finding in
MOGO-002.5, 002.6, or 002.7.**

## 3. Which artifacts appear intentional

**Nearly all of it.** Three independent signals:

1. **`.gitignore` is already correct and working.** It is purpose-written for this project (not a
   generic template) and covers macOS metadata, editor backups, `*.tmp`, `__pycache__`, `*.pyc`, and
   `.claude/settings.local.json`. **Zero untracked files match any noise pattern** — no `.DS_Store`,
   no stray `.tmp` from the atomic-write helper, no `__pycache__`. Verified by direct search.
2. **Every file sits in a documented location.** `docs/trader-intelligence/README.md` §"Directory
   layout" describes the tree that exists on disk, including the note that *"empty directories are
   never created as placeholders."*
3. **The content is schema-valid and integrity-clean.** The graph build reports **zero findings** and
   evidence integrity reports **0**; 11 sources trace to 11 registered intakes with content hashes.

## 4. Which files may be generated noise — one real candidate

**`docs/trader-intelligence/evidence/lifecycle/` — 3,634 files, 14 MB.** This is **54% of the untracked
file count and half the evidence store's size**, and it is the one area worth an explicit decision
rather than a blanket commit.

**Measured:**

| | |
|---|---|
| Total lifecycle events | **3,634** |
| `confidence_recomputed` | **2,403** |
| …of which record **no state change** (`priorStatus == newStatus`) | **2,080 — 86.6%** |
| `created` / `linked` / `status_changed` / `corrected` / `other` | 727 / 435 / 55 / 3 / 11 |

**So ~2,080 files exist to record that nothing happened.** Filenames are opaque 32-hex digests, so
they are also undiffable in review. This is not a defect — an append-only audit log doing exactly what
it was built to do — but it is worth the Authority knowing that committing it as-is bakes in a log
whose dominant content is no-op recomputes, and that it will keep growing multiplicatively (claims ×
recomputes) with every ingestion.

**It is also incidental evidence for D2:** 2,080 recorded non-movements are the same finding the Rayner
cycle reached — adding sources does not move confidence under trader-scoped fingerprinting.

**Recommendation: commit it as-is now, and open a separate proposal for retention policy.** Do not
prune during a stabilization commit — pruning an append-only provenance log while trying to establish
a baseline mixes two unrelated risks.

## 5. Risks of continuing without a baseline commit

| # | Risk | Likelihood | Impact |
|---|---|---|---|
| **RS-1** | **Total loss of ~32 MB of research** to `git clean -fd`, a bad `checkout`, or disk failure. The working tree is the only copy. | **Medium** | **Critical** |
| **RS-2** | **Raw transcripts are unrecoverable.** 11 transcripts in `imports/*/raw/` with SHA-256 sidecars. YouTube transcripts are **not reliably re-obtainable** — MOGO-002.7 just demonstrated exactly that failure against a target video. | Medium | **Critical** |
| **RS-3** | **Three Engineering Review Packages exist only as untracked files.** The normative record of what each milestone found and decided. | Medium | **High** |
| **RS-4** | **No milestone is attributable or revertible.** Three milestones and five research cycles are one undifferentiated blob; there is no way to revert 002.6 without also reverting 002.5, or to bisect a regression. | **Certain** | Medium |
| **RS-5** | **`index.html`'s 113 insertions are uncommitted**, so the only behavioural change in the set is also the one most exposed to accidental loss or accidental inclusion in an unrelated commit. | Medium | Medium |
| **RS-6** | Baseline `APP_VERSION` (12.5.0) lags `index.html` (12.6.0). Disclosed, drift-clean, but every future drift check reports the mismatch — noise that trains reviewers to ignore the check. | Certain | Low |
| **RS-7** | Each additional cycle makes the eventual first commit harder to review, increasing the chance it is approved unread. | **Certain** | Medium |

**RS-2 is the one to weigh most heavily.** Everything else in the untracked set is either regenerable
(graph builds, KE artifacts, reports) or re-derivable. The raw transcripts are neither — and this
milestone just proved that re-acquiring a YouTube transcript can fail outright.

## 7. The obsolete-test decision, which blocks a clean commit

**4 tests fail, unchanged since 2026-07-27:** `test_expected_node_and_edge_counts`,
`test_production_evidence_tree_is_still_genuinely_empty`,
`test_production_graph_unchanged_without_real_corpus`,
`test_production_graph_unchanged_without_real_knowledge_library`.

All four assert **the production evidence tree is empty** — false since the first real ingestion, and
they fail in a way that *looks* like a regression and is not. `docs/TESTING.md` already records the
correct fix in principle: *"Prefer invariants over emptiness… Assert what must remain true… rather
than what merely happens to be true today."*

**This matters for stabilization** because committing the tree with 4 red tests establishes a baseline
that is not green, and every future run has to re-explain them. The decision is small: **rewrite the 4
assertions as invariants, or delete them as superseded.** It has been open since 2026-07-27.
