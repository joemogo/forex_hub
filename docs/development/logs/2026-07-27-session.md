## Workflows implemented

**Two-phase ingestion.** Phase 1 (`ingest.py <file> --trader X`) verifies, hashes, duplicate-checks,
archives, normalizes reversibly, proposes sections, and emits a draft manifest — registering nothing.
Extraction judgment happens by filling in the manifest. Phase 2 (`ingest.py --apply <manifest>`)
validates fail-closed, then registers, applies, builds the library in the correct order, rebuilds the
graph, validates integrity, regenerates the dashboard, collapses duplicate queue entries, and moves
the file to `completed/`.

**Supporting workflows:** provenance re-verification · rollback with orphan collection · dashboard
regeneration after every ingestion · Trader Intelligence Review every 10 ingestions · research-log
entry with a six-point ROI review every cycle.

# Decisions

## Engineering decisions

1. **Normalization must be provably reversible.** `timestamp + removedLabel + normalizedText ==
   source line`, asserted per line; the run aborts on failure. Only YouTube duration labels were
   removed — 10,300 characters, zero words.
2. **Sections are cut for traceability, not narrative.** Every source line covered exactly once
   (asserted); boundaries moved rather than splitting a quotable sentence; mid-sentence starts
   flagged, not hidden.
3. **Extraction judgment is not automated.** The CLI automates everything around it and stops. No
   LLM call inside the pipeline; the no-network guarantee is preserved.
4. **Build the profile last.** It counts hypotheses at build time and the report reads its
   statistics off it, so the documented order produced `hypothesisCount: 0` (defect D3).
5. **Fail-closed validation.** A single changed character fails `--apply` with nothing written.
6. **Two-phase separation.** Nothing enters the evidence store until a reviewable manifest exists.
7. **Assert structure, not counts.** Revised an earlier recommendation after `TRADER` and
   `OWNER_DECISION` both incremented: a count of things the system accumulates is not a regression
   guard.
8. **Generate status, never hand-maintain it.** Every hand-maintained status document in this
   repository had gone stale, including the front-door README.
9. **No parallel archive tree.** Raw and normalized archives already existed per-trader under
   `imports/{trader}/`; duplicating them would create two sources of truth.
10. **`subprocess.run` with argv, not `os.system`.** The repository path contains a space.

## Filename format

```
{trader-slug}-{topic-slug}.txt
```

Lowercase, hyphen-separated, no spaces. The stem becomes the manifest name, so keep it stable and
descriptive. Examples: `ict-2022-mentorship-ep01.txt` · `alexg-support-resistance-masterclass.txt` ·
`tjr-risk-management.txt`.

Accepted content: plain text, timestamped text, or structured JSON. The normalization profile is
auto-detected and reported; override with `--normalize-profile`.

## Processing workflow

| Step | Who | Action |
|---|---|---|
| 1 | Owner | Drop the file in `intake/pending/` |
| 2 | CLI | `ingest.py <file> --trader X` — verify, hash, duplicate-check, archive, normalize, section, draft manifest, `pending → processing`. **Registers nothing.** |
| 3 | Researcher | Fill `annotations` in `intake/manifests/{slug}.ingest.json` per `STANDARDS-extraction.md`. **The only judgment step.** |
| 4 | CLI | `ingest.py --apply <manifest> --dry-run` — fail-closed validation, writes nothing |
| 5 | CLI | `ingest.py --apply <manifest>` — register, apply, build library, rebuild graph, validate, regenerate dashboard, `processing → completed` |
| 6 | Researcher | Update research log (with ROI review), glossary, cross-strategy analysis, replay candidates, acquisition backlog |
| 7 | Owner | Review; run regression suites |

**Trader ID must exist first.** Registered: `TJR`, `ICT`, `ALEX_G`, `JVM`. To add another, create
`traders/{id}/profile.json` first — `ingest.py` refuses without one. Only assert `markets` and
`instruments` you can evidence: an unevidenced value is carried into the Knowledge Library as
`confirmed` and silently outranks real evidence (defect D1).

**Optional metadata flags:** `--title`, `--url`, `--channel`, `--published`, `--provider`,
`--licensing`, `--completeness`.

**Expected outcome for a single new source:** claims at `emerging`, zero rule candidates. A non-zero
rule-candidate count means a claim was corroborated by two or more independent sources — verify that
is genuinely the case.
