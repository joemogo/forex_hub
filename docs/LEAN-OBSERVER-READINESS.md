# Disabled LEAN observer readiness — September 2, 2026

## Decision

The local synthetic H1 observer/export path is **ready for a separately reviewed
browser-integration design**, but is **not ready to install, enable, or use with
real forward data**. Paper trading readiness is not assessed.

## Proven in the reviewed branch

- The disabled observer detects one newly produced B&R and exports contract v2
  entirely in memory. There is no application call site, timer, storage, network,
  upload, paper position or order behavior.
- Downward/support and upward/resistance synthetic paths are generated by the
  actual unchanged MOGO engine, exported by the JavaScript emitter, and accepted
  by the local Python v2 boundary with matching break, retest and qualification
  indices.
- Each engine attempt owns fresh state and copied candles. A post-mutation fault
  is discarded and the pending export recovers once without altering the caller
  or a separate engine.
- Stale/future clocks, backward time, revised history, discontinuities, malformed
  bars, contradictory provenance and declared/evaluated break mismatch refuse.
- The test-only H1 source factory avoids application initialization. It is not a
  production module, general parser, browser sandbox or multi-timeframe engine.
- The one-close default is covered. Counts 2 and 3 are explicitly unsupported in
  these fixtures and require a governed strategy-semantics decision.

## Required next authority and operator work

1. Approve a production integration design review. It must choose an isolated
   browser execution boundary without reusing or resetting the running scanner.
2. Resolve synchronous observer versus asynchronous browser-worker messaging,
   CSP/module loading, trusted clock, maximum age and source identity.
3. Approve and validate market-session/calendar handling. Current H1 continuity
   conservatively refuses weekend and holiday gaps; bars must not be fabricated.
4. Separately decide whether multi-close role semantics should change. This would
   touch protected strategy behavior and is not required for the one-close default.
5. After reviewed integration is installed on the Mac, run real Chrome validation.
   Then use the already separate authorization boundary for one read-only forward
   capture with exact source candles and provenance.
6. Cloud LEAN execution and paper-trading readiness remain separate milestones.

No observer result establishes broker isolation, sizing, stops/targets, P&L,
position persistence, shutdown behavior or duplicate-order protection. Do not
turn on paper trading based on this milestone.
