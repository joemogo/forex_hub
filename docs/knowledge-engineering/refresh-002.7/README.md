## Why these are in a subdirectory

`build_ke_artifacts.py` writes into `docs/knowledge-engineering/` directly, so running it **overwrote
MOGO-002.6's ten JSON artifacts in place.** Those are the deliverables of a milestone that is still
awaiting review, and **nothing in this repository is committed**, so an in-place overwrite would have
destroyed them permanently with no way to recover.

The refreshed outputs were therefore moved here and **all 21 MOGO-002.6 artifacts were restored and
verified byte-identical (21/21)**. This follows the same principle as MOGO-002.7's other artifacts:
write to your own location, never mutate a prior milestone's record.

**To adopt this refresh**, the Authority need only approve moving these ten files up one level — and
should read §3 first.

## 3. ⚠️ Two defects in the refresh, disclosed

**D-1 — The nine Markdown reports were NOT regenerated and are now stale relative to this JSON.**
`build_ke_artifacts.py` writes **only the twelve JSON files**; it contains no Markdown writer.
MOGO-002.6's nine `.md` reports (`ALEX-STRATEGY-SPECIFICATION-V2-DRAFT.md`, `HUMAN-REVIEW-QUEUE.md`,
and seven others) are **not reproducible from the committed generator** and must have been produced by
a step that was not retained.

This is a genuine reproducibility gap in MOGO-002.6, found by MOGO-002.7 and reported rather than
patched. **Consequence: if this refresh is adopted, those nine reports must be regenerated by some
means, or they will assert 111 rules while the JSON asserts 127.** They are currently consistent only
because the JSON was restored.

**D-2 — The draft's `provenanceNote` is hardcoded and did not update.** It still reads *"Derived from
the ALEX_G educator claim library (195 claims, 8 source artifacts)"* while describing 226 claims from
9 sources. A one-line fix in `build_ke_artifacts.py`, not applied here because this milestone is not
authorized to change the KE generator's behaviour.

**D-3 — ⚠️ Running the KE test suite regenerates these artifacts in place.**
`tests/knowledge_engineering/test_knowledge_engineering.py` calls `generate_all()` three times, and
`generate_all()` writes into `docs/knowledge-engineering/`. **A routine test run silently rewrites the
parent directory's ten JSON artifacts from whatever is currently in the evidence store.**

Found the hard way during this milestone: the originals were restored, a test run overwrote ten of
them again, and they had to be restored a second time (re-verified 21/21 byte-identical).

**If you run `python3 -m unittest tests.knowledge_engineering.test_knowledge_engineering`, expect the
parent directory's JSON to become the 226-claim version** — i.e. a copy of this folder — and restore
from version control (once committed) if that is not what you wanted.
